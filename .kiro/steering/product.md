# Product Overview

Amark は Markdown テキストをパースする C99 ライブラリである。テキストを木（AST）へパースし、木を編集し、HTML と Markdown へレンダリングする。アプリケーションや他言語バインディングに組み込まれる部品として、C から直接使う開発者に提供する。

## Core Capabilities

- **パース**: Markdown テキストを木に変換する
- **拡張可能な構文解析**: 構文は拡張として登録し、拡張の組み合わせで CommonMark や GFM などの方言を表現する
- **木の編集**: ノードの値は木が所有し（cmark 方式）、API で読み書き・挿入・取り外し・置換ができる
- **レンダリング**: 木を HTML と Markdown の両方へ出力する

## Target Use Cases

- Markdown を HTML に変換して表示する
- 文書を木として読み込み、機械的に書き換えて Markdown として書き戻す
- 必要な構文だけを選んだ方言、あるいは独自構文を足した方言でパースする
- パーサを介さず API で木を組み立てて出力する

## Value Proposition

- **方言を組み立てられる**: パーサエンジンは個々の構文を知らない。CommonMark の構文もライブラリ外の拡張も同じ公開 API で登録するため、構文の追加だけでなく取り外しや差し替えもできる
- **1 つの拡張で完結する**: 拡張は構文、ノード種別、HTML 出力、Markdown 出力をまとめて提供できる
- **組み込みやすい**: C99 のみに依存し、静的・動的ライブラリの両方を Windows / Linux / macOS で提供する。メモリ確保はグローバルアロケータの差し替えで制御できる

## Non-Goals

- **ロスレス**: 原文を一字一句復元することは目的としない。Markdown 出力は正規化した記法になる
- **HTML サニタイザ**: 生 HTML を出力するかどうかの切り替えに留める

## Product Principles

- **仕様適合を既定にする**: CommonMark 方言は CommonMark 仕様の例をすべて通す
- **信頼できない入力を前提にする**: 病的な入力でも処理時間とメモリが爆発しない
- **あるべき姿を spec の境界より優先する**: エラーコードや API の流儀はライブラリ全体で一貫させ、必要なら完了済みの spec に遡って直す
