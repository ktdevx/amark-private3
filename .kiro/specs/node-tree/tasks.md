# Implementation Plan

> 前提: foundation の実装（ビルドの骨組み、エラー列挙、アロケータ、スライス、UTF-8、テスト基盤と差し替えアロケータ）が完了していること。本計画のタスクはすべて foundation の公開 API とテスト登録の規約の上に積む。
>
> 並行実行について: 各モジュールのタスクはライブラリのソース一覧とテスト登録の同じビルド定義ファイルに追記し、さらに実装順の依存（種別 → レジストリ → ノードの寿命 → 値・編集 → 走査・正規化 → 振り分け走査）があるため、`(P)` を付けられるタスクはない。

## Implementation Notes
- 1.2: node_kind.h / node_iter.h は amark_error_t を返す関数のため設計の include 一覧に加えて <amark/error.h> を include する。amark_node_iter_get_event(NULL) の戻り値はヘッダ未記載で、4.1 で決めてヘッダとテストに記す
- 3.1: amark_node_release_values は解放したフィールドを未設定へ戻す（二重呼び出し安全）。3.2 の set_data は置き換え時の後片付けを自前で行い release_values を呼ばない。親付きの取り外し・破棄と深さ 10 万段の破棄のテストは 3.3 で追加する
- 3.2: set_data は新しい値を格納してから旧データの後片付けを呼ぶ（設計の記述順と逆だが、コールバック中にノードが解放済みデータを指さない。要件 5.x の観測結果は同じ）。文字列の空値は未設定に戻り、取得は static の "" を返す
- 4.1: amark_node_iter_get_event(NULL) は AMARK_NODE_ITER_DONE を返す。next は R でない現在ノードが親を失っていれば移動前に DONE を返す。現在ノードの祖先（R でない）の取り外し後は reset まで結果未規定とヘッダに記した。**要人間レビュー**: design.md の安全性規則の表（l.767「N またはその祖先の取り外し → 次の next は DONE」）は手順（l.748–753）・状態図と食い違う。祖先の検出は next ごとに O(深さ) を要し 13.1 と両立しないため、表を「祖先の取り外しは reset まで未規定」に改める設計修正が必要
- 4.3 向け: 振り分け走査はイテレータの reset で同じノードの EXIT へ移す（reset の部分木検査は O(深さ)。省略のたびに呼ぶと深い木で O(n·深さ) になりうる点に注意）
