# Implementation Plan

> 前提: foundation の実装（ビルドの骨組み、エラー列挙、アロケータ、スライス、UTF-8、テスト基盤と差し替えアロケータ）が完了していること。本計画のタスクはすべて foundation の公開 API とテスト登録の規約の上に積む。
>
> 並行実行について: 各モジュールのタスクはライブラリのソース一覧とテスト登録の同じビルド定義ファイルに追記し、さらに実装順の依存（種別 → レジストリ → ノードの寿命 → 値・編集 → 走査・正規化）があるため、`(P)` を付けられるタスクはない。

- [ ] 1. 基盤: エラーコードの追加と公開ヘッダの宣言
- [ ] 1.1 共通のエラー列挙に木のための 2 つのコードを追加する
  - 「不正な子（親子関係の規則違反・循環・document を子にする）」と「既に存在する（名前の重複）」を、次の連番の明示値で末尾に追加する。既存の値は変えない
  - 各コードに固有の英語の短い説明を返すようにし、列挙・文字列化・エラーのテストを同時に更新する
  - 完了状態: エラーのテストで 2 つのコードの値と、未知のエラーとは異なる固有の文字列が確認され成功し、警告エラー化の構成で文字列の定義漏れがない
  - _Requirements: 12.1_

- [ ] 1.2 種別・ノード・イテレータの公開ヘッダを宣言し、利用者の義務と安全性規則を文書化する
  - 設計どおりの種別の識別値（標準 18 種と拡張共通値）、分類、内容モデル、種別記述子とコールバック型、レジストリ、ノード、リスト種別、値の範囲の定数、イテレータの構造体とイベントを宣言する
  - レジストリをその種別のノードより先に破棄してはならないこと、コールバックの中で木やレジストリを変更しないこと、判定関数は決定的であること、異なる木は別スレッドで同時に操作してよいが同じ木はいけないこと、登録が終わったレジストリは複数スレッドから使ってよいことをヘッダのコメントに記す
  - イテレータのヘッダに、走査中に安全な編集と、走査位置の設定し直しが必要な編集の一覧を記す
  - 3 つのヘッダを包括ヘッダに追加し、steering の命名の例にあるノード生成関数の形を、エラーを返し出力引数で結果を返す確定した形に直す
  - 完了状態: ヘッダ単独 include 検査で 3 つの新しいヘッダが単独でコンパイルでき、既存のテストがすべて成功する
  - _Requirements: 2.1, 2.2, 2.3, 4.10, 10.5, 13.3, 13.4_

- [ ] 2. 種別とレジストリ
- [ ] 2.1 非公開の共有定義、標準種別の表、種別の問い合わせと受け入れ判定を実装する
  - 種別とノードの構造体、所有文字列、モジュール間の内部関数を非公開ヘッダに定義する（公開ヘッダからは include せず、内部関数は動的ライブラリから公開しない）
  - 18 の標準種別を、変更されない定数の表として、識別値・名前・分類・内容モデル・明示親限定（item）・子にできない（document）・list の「item だけ」の判定とともに定義する
  - 識別値から標準種別を得る問い合わせ、種別から識別値・名前・分類・内容モデルを得る問い合わせ、親子の受け入れ判定を設計の手順どおりに実装する
  - ソースをライブラリに、種別のテスト実行ファイルを CTest に登録する
  - 完了状態: 種別のテストで 18 種別の値・名前・分類・内容モデル、未定義の値に対する「ない」結果、同じ値に常に同じ種別が返ること、18 × 18 の受け入れ判定表が設計どおりであることが確認され成功する
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 6.1, 6.2, 6.6_

- [ ] 2.2 拡張ノード種別のレジストリを実装する
  - レジストリの生成・破棄、名前の形式（1〜64 バイト、英小文字で始まり英小文字・数字・下線のみ）と記述子の矛盾の検証、標準名と既登録名の重複の拒否、名前の複製を伴う登録、名前による検索を実装する
  - 種別は個別に確保してハンドルを不変に保ち、失敗時は途中の確保をすべて戻す
  - ソースとレジストリのテスト実行ファイルを登録する
  - 拡張種別の内容モデル（任意のブロック、任意のインライン、子なし、独自判定）と明示親限定が受け入れ判定に反映されることをテストする
  - 完了状態: レジストリのテストで登録・検索・名前の境界・重複・矛盾・多数登録後のハンドルの不変・名前バッファの書き換えに影響されないこと・拡張種別の受け入れ判定が確認され、失敗注入の網羅パターンで各失敗が状態を変えず、破棄後に生存ブロック数が 0 になる
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 4.7, 4.8, 4.9, 6.3, 6.4, 6.5, 12.2, 12.3, 12.4, 12.6, 13.4_

- [ ] 3. ノードの寿命・値・編集
- [ ] 3.1 ノードの生成・取り外し・破棄・参照を実装する
  - 標準種別の識別値または種別ハンドルからの生成（既定値の設定、未知種別の拒否）、親・子・兄弟の参照、種別の取得を実装する
  - 取り外し（兄弟のつなぎ直しと所有の移転）と、値の解放（所有文字列と拡張種別の付随データの後片付けの呼び出し）を実装する
  - 破棄は親を持てば先に取り外し、部分木を後行順の反復で解放して、木の深さに比例するスタックを使わない
  - ソースとノードのテスト実行ファイルを登録する
  - 完了状態: ノードのテストで標準・拡張の生成と初期リンク、未知種別と空ポインタの拒否、根の取り外しが何もしないこと、空ポインタの破棄、生成の失敗注入、破棄後に生存ブロック数が 0 であることが確認され成功する
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.7, 2.4, 7.4, 7.5, 8.2, 12.3, 12.4, 13.3_

- [ ] 3.2 種別ごとの値のアクセサと付随データを実装する
  - 見出しレベル、リスト種別・開始番号・tight、literal、info、URL、タイトルの読み書きを、設計の値の表（対象種別、既定値、範囲）どおりに実装する
  - 文字列の設定は、スライスの不変条件、サイズのあふれ、UTF-8 の妥当性を検査してから複製し、成功した後で旧値を解放する。取得は、値を持つ種別では末尾が NUL の借用文字列、持たない種別では参照先のない空の借用文字列を返す
  - 付随データの設定（同一値は何もしない、置き換え時に旧データの後片付けを 1 回、標準種別は拒否）と取得を実装する
  - ソースと値のテスト実行ファイルを登録する
  - 完了状態: 値のテストで既定値、往復、範囲の境界、不正な UTF-8、NUL を含む値、呼び出し側の文字列を書き換えても値が変わらないこと、種別不一致、あふれ、失敗注入で旧値が残ること、付随データの後片付けの回数（置換・同一値・破棄・後片付けなし）が確認され成功する
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.8, 3.9, 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 12.3, 12.5_

- [ ] 3.3 親子規則を検証する編集操作を実装する
  - 末尾追加・先頭追加・前後への挿入・置換を、設計の検証順（引数、親の有無、循環、受け入れ判定）で、すべての検証がリンクの変更前に終わるように実装する
  - 既に親を持つノードは検証の後で取り外してから置き（移動）、置換では置き換えるノードが対象の部分木内にあってもよいようにする
  - 循環の検査は、動かすノードが子を持つ場合だけ新しい親から祖先をたどる
  - ソースと編集のテスト実行ファイルを登録する。木を組む必要のある参照・取り外し・破棄の確認もここで行う
  - 完了状態: 編集のテストで各操作後の親・兄弟・最初と最後の子の整合と参照の結果、移動、引数エラー、規則違反と循環が不正な子のエラーになり全ノードのリンクが不変であること、親を持つノードの破棄後の残りの木の整合と生存ブロック数 0、深さ 10 万段の木を上から下へ組んで破棄する処理が完了することが確認され成功する
  - _Requirements: 1.4, 1.5, 1.6, 6.7, 6.8, 7.1, 7.2, 7.3, 7.4, 7.6, 7.7, 7.8, 8.1, 8.3, 13.1, 13.2_

- [ ] 4. 走査と正規化
- [ ] 4.1 enter / exit イテレータと位置の再設定を実装する
  - 呼び出し側が領域を持つイテレータを、確保なしに、次の位置を呼び出しのたびに現在ノードのリンクから計算する方式で実装する。葉の種別は enter だけ、子を取れる種別は enter と exit を報告し、起点の外へ出ない
  - 終了後も終了を報告し続け、起点でないノードが親を失っていれば終了を報告する
  - 位置の再設定を、起点の部分木内のノードと enter / exit に限って受け付け、葉への exit を拒否する
  - ヘッダの安全性規則の一覧に、現在ノードを破棄して走査を続ける手順の例を加える
  - ソースとイテレータのテスト実行ファイルを登録する
  - 完了状態: イテレータのテストで代表的な木のイベント列の完全一致、空のコンテナと葉の扱い、部分木限定、終了の継続、再設定の正常系とエラー、走査中の確保回数 0、走査中の安全な編集（値の変更、未報告の兄弟の削除、enter 時の子の追加）の結果、現在ノード取り外し後の終了と再設定による再開、深さ 10 万段の走査が確認され成功する
  - _Requirements: 9.1, 9.2, 9.3, 9.4, 9.5, 9.6, 10.1, 10.2, 10.3, 10.4, 10.5, 13.1_

- [ ] 4.2 隣接テキストの結合と空テキストの除去を行う正規化を実装する
  - 起点の部分木を反復で走査し、子の並びの中の連続する text ごとに、空の text を取り除いてから残りを 1 回の確保で連結する。起点自身は取り除かない
  - 連結長のあふれを確保前に検出し、確保に失敗した並びは連結を行わずに処理を止める
  - ソースと正規化のテスト実行ファイルを登録する
  - 完了状態: 正規化のテストで結合・空の除去・text 以外による区切り・強調の中の並び・起点が空の text の場合・冪等性・他ノードの不変が確認され、失敗注入の網羅パターンで各回の木が親子規則を満たし並びごとの連結内容が元と同じで後片付け後の生存ブロック数が 0、深さ 10 万段の木の正規化が完了する
  - _Requirements: 11.1, 11.2, 11.3, 11.4, 11.5, 12.5, 13.1_

- [ ] 5. 統合と最終検証
- [ ] 5.1 API だけで文書木を組む統合シナリオと C++ からの利用を検証する
  - 見出し、強調・リンク・コードスパンを含む段落、2 項目のリスト、コードブロック、独自判定で拡張の行だけを受け入れる拡張ブロック（表と行）を API だけで組み、走査、特定種別の置換、正規化、破棄までを通すシナリオテストを加える
  - C++ の検査に、木の生成・子の追加・走査・破棄の呼び出しを加える
  - 完了状態: シナリオテストのイベント列と値が期待どおりで、根とレジストリの破棄後に生存ブロック数が 0 になり、C++ の検査がビルド・リンク・実行に成功する
  - _Depends: 2.2, 3.3, 4.1, 4.2_
  - _Requirements: 1.6, 6.4, 12.6_

- [ ] 5.2 静的・動的の両構成で全テストと公開シンボルを検証する
  - 警告をエラーとする設定で静的・動的の両方を構成・ビルドし、foundation と node-tree のすべてのテストを実行する
  - 動的ライブラリの公開シンボルに非公開ヘッダの内部関数が含まれないこと、node-tree のソースが標準の確保関数を直接呼ばず、可変のグローバル変数を持たないことを確認する
  - 完了状態: 両構成ですべてのテストが成功し、公開シンボルが設計の公開関数だけであり、node-tree のソースに標準の確保関数の直接呼び出しと可変のグローバル変数がない
  - _Requirements: 12.2, 13.3, 13.4_
