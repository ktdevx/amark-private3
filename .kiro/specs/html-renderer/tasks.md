# Implementation Plan

> 前提: foundation（ビルドの骨組み、エラー列挙、アロケータ、スライス、バッファ、テスト基盤と差し替えアロケータ）と node-tree（種別、レジストリ、ノード、値のアクセサ、編集、イテレータ、子の省略後の EXIT も訪問する非公開の振り分け走査 `src/tree/node_walk.h`）の実装が完了していること。本計画のタスクはすべてそれらの公開 API、node-tree の振り分け走査、テスト登録の規約の上に積み、振り分け走査は変更しない。
>
> 並行実行について: 各タスクはライブラリのソース一覧とテスト登録の同じビルド定義ファイルに追記し、さらに実装順の依存（符号化 → 組み込み出力 → 描画の入口 → フック）があるため、`(P)` を付けられるタスクはない。

- [ ] 1. 基盤: 公開ヘッダとテスト用の木の組み立て補助
- [ ] 1.1 HTML レンダラの公開ヘッダを宣言し、利用者の義務を文書化する
  - 設計どおりに soft break の出力方法の列挙、設定の構造体、レンダラとコンテキストの不透明型、フック関数の型、設定・レンダラ・単発描画・コンテキスト操作・エスケープと URL のユーティリティの関数を宣言する
  - ヘッダ冒頭に、フックから木を変更しないこと、コンテキストをフックの呼び出しの外で使わないこと、描画中にフック登録や破棄をしないこと、フックの種別ハンドルの出所（node-tree のレジストリ、または parser-core の拡張とそれを所有する方言）をレンダラより長く生かすこと、登録後のレンダラは異なる出力先へ複数スレッドから同時に描画してよいことを記す
  - フックの登録にはパーサや拡張の仕組みが要らず、標準種別・拡張種別のハンドルだけで行えることをコメントで示す
  - 包括ヘッダに新しいヘッダを追加する
  - 完了状態: ヘッダ単独 include 検査で新しいヘッダが単独でコンパイルでき、既存のテストがすべて成功する
  - _Requirements: 10.8, 11.8, 12.1, 13.3_

- [ ] 1.2 テスト用の木の組み立て補助をテスト補助ライブラリに追加する
  - 標準種別のノードの生成、文字列の値を持つノード（text、code、HTML、コードブロック）の生成、リンク先とタイトルを持つ link / image の生成、子の追加を、node-tree の公開 API だけで行う補助を作る
  - 失敗時は補助の側で生成途中のノードを破棄し、空の結果を返す
  - 補助はテスト補助ライブラリにだけ含め、ライブラリ本体には含めない
  - 完了状態: テスト補助ライブラリがビルドでき、補助で組んだ木を破棄した後に計測アロケータの生存ブロック数が 0 になることを確認する最小のテストが成功する
  - _Requirements: 1.3_

- [ ] 2. 符号化
- [ ] 2.1 HTML エスケープ、URL 符号化、危険な URL 判定を実装する
  - 設計のエスケープ表（4 文字の置換、他はそのまま）と URL 安全文字表（安全文字はそのまま、`&` と `'` は実体参照、その他は大文字 16 進の `%XX`、既存の `%` は再符号化しない）を変更されない定数の表として持つ
  - 危険な URL は大文字小文字を区別しない接頭辞一致で 4 つのスキームを危険とし、4 種の画像の data URL を除外する
  - 長さどおりに処理して NUL で止まらず、失敗時は出力先を呼び出し時の長さに戻す
  - エスケープのテスト実行ファイルを登録する
  - 完了状態: エスケープのテストで各置換と素通し、URL の安全文字・非安全文字・非 ASCII（`ä` → `%C3%A4`）・既存の `%`、危険な URL の 4 スキームと大文字混在・画像 data URL の許可・その他の data URL の拒否・先頭空白・空、引数エラー、失敗注入で出力先の長さが戻ることが確認され成功する
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5, 7.5, 12.3_

- [ ] 3. 組み込み出力と描画の入口
- [ ] 3.1 設定、レンダラの寿命、描画の入口と巻き戻しを実装する
  - 設定の初期化（生 HTML と危険な URL を抑止、soft break は改行）と検証（soft break の未定義値を拒否）を実装する
  - レンダラの生成（設定の複製、フック表の初期化、確保失敗で出力引数を変えない）と破棄、単発の描画、レンダラによる描画を実装する。描画は確保なしでコンテキストを用意し、node-tree の振り分け走査を回し、失敗時に出力先を開始時の長さへ戻す
  - 訪問関数は振り分け走査から渡されたフックがあればフックを、なければ組み込み出力を呼ぶ。この時点の組み込み出力は行頭保証（このレンダリングの出力だけを見る）と、document・paragraph（tight 判定なし）・text の出力と、未知の種別に何も出さない透過だけを持つ
  - 描画のテスト実行ファイルを登録する
  - 完了状態: 描画のテストで引数エラー、既存内容への追記（既存内容が改行で終わらなくても先頭に改行を足さない）、段落や text を起点にした部分木の描画、同じ入力での同一出力、描画前後で木の値とリンクが不変、未定義の soft break の拒否、レンダラの破棄後に生存ブロック数が 0 であることが確認され成功する
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 1.7, 8.4, 10.9, 12.3, 12.5, 12.6, 13.4_

- [ ] 3.2 標準ブロック種別の組み込み出力と tight / loose を実装する
  - 設計の組み込み出力の表に従い、block quote、箇条書き・番号付きの list（開始番号 1 とそれ以外）、item、heading、thematic break、code block（info の最初の空白の前を言語名とし、`language-` 始まりでは接頭辞を重ねない）、HTML block（設定に応じて内容そのままか省略の注記、前後の改行規則）、paragraph を出力する
  - 段落の親が item でその親が tight な list のときだけ段落のタグを出さない。部分木を起点にしても親リンクから判定する
  - ブロックのテスト実行ファイルを登録する
  - 完了状態: ブロックのテストで表の全行、開始番号 0・1・2・999999999、見出し 1〜6、info の空・1 語・複数語・タブ区切り・`language-` 始まり・特殊文字、空の段落と空の item、行頭保証の位置、tight / loose の入れ子と tight なリスト内のコードブロック、部分木起点の tight 段落が期待どおりの HTML になり成功する
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7, 2.8, 2.9, 2.10, 2.11, 2.12, 3.1, 3.2, 3.3, 3.4, 7.1, 7.2_

- [ ] 3.3 標準インライン種別と画像の alt 平坦化を実装する
  - code span、emphasis、strong、line break、soft break（設定に応じた 3 方式）、HTML inline（設定に応じて内容そのままか省略の注記）、link（設定を適用した URL、空でないタイトルだけ属性に出す）を出力する
  - image は ENTER で src・alt・title の順に属性を出して閉じ、画像を起点にした内側のイテレータで子孫の text・code・HTML inline の内容をエスケープし、soft / line break を空白にして alt にする。強調・リンク・入れ子の画像のタグは出さず、フックも呼ばない。外側の走査には子の省略を要求し、EXIT では何も出さない
  - 危険な URL は許可されていなければ link と image の属性値を空にする
  - インラインのテスト実行ファイルを登録する
  - 完了状態: インラインのテストで各種別の出力、タイトルあり・なし・特殊文字の link、image の属性順、強調・リンク・入れ子の画像・code・HTML inline・改行を含む alt の平坦化、危険な URL の link と image が期待どおりの HTML になり成功する
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 4.7, 4.8, 5.1, 5.2, 5.3, 5.4, 7.3, 7.4, 8.1, 8.2, 8.3_

- [ ] 3.4 安全性と soft break の設定の組み合わせを検証する
  - 設定のテスト実行ファイルを登録し、既定値、生 HTML の抑止と許可（block と inline、block の前後の改行）、危険な URL の抑止と許可（link と image）、2 つの許可を独立に切り替えた 4 通り、soft break の 3 方式と未定義値の拒否、生 HTML を許可しても内容を変形しないことを確認する
  - 完了状態: 設定のテストが上記の全組み合わせで期待どおりの HTML とエラーを確認して成功する
  - _Requirements: 7.1, 7.2, 7.3, 7.4, 7.6, 7.7, 8.1, 8.2, 8.3, 8.4_

- [ ] 4. レンダラフック
- [ ] 4.1 フックの登録とコンテキスト操作を実装する
  - レンダラへのフック登録（種別が空なら拒否、既存は置き換え、空の関数で解除、確保失敗で表を変えない）を node-tree の振り分け走査の表の上に実装し、関数ポインタの型変換を登録と呼び出しの 2 か所に限る
  - コンテキストのそのままの出力、エスケープ出力、安全性の設定を適用した URL 出力、行頭保証、子の省略（振り分け走査の子の省略を要求し、省略したノードの EXIT でもフックが呼ばれる）、現在のノードとイベントについての組み込み出力への委譲、設定の参照を実装する
  - フックのテスト実行ファイルを登録する
  - 完了状態: フックのテストで拡張種別への追加（子を取る種別は ENTER / EXIT の 2 回、葉は 1 回）、標準種別の上書き、置き換え、解除で元の出力に戻ること、空の種別の拒否、利用者データの受け渡し、子の省略（ENTER で子を省略したノードの EXIT でフックがちょうど 1 回呼ばれ子孫は呼ばれないこと、その EXIT のフックのエラーで中止され出力先が戻ること、image の ENTER で組み込みに委譲した後も image の EXIT でフックが呼ばれること）、image を含む組み込み出力への委譲、未登録の拡張種別の透過、alt の中でフックが呼ばれないこと、フックのエラーで中止され出力先が戻ること、各コンテキスト操作と設定の参照が確認され成功する
  - _Requirements: 5.5, 10.1, 10.2, 10.3, 10.4, 10.5, 10.6, 10.7, 10.8, 11.1, 11.2, 11.3, 11.4, 11.5, 11.6, 11.7, 12.4_

- [ ] 4.2 拡張種別を含む文書のシナリオを検証する
  - レジストリに拡張ブロック種別を登録して得たハンドル（名前による検索で得たものを含む）でフックを登録し、拡張ノードを含む文書を手組みして描画する
  - 同じ文書を、標準の link を上書きして条件により組み込みへ委譲するレンダラでも描画する
  - パーサを使わずに、種別ハンドルだけで結び付けられることを確認する
  - 完了状態: 両方の描画が期待 HTML と一致し、木・レンダラ・レジストリの破棄後に生存ブロック数が 0 になるシナリオテストが成功する
  - _Requirements: 10.1, 10.2, 10.3, 10.8, 11.6_

- [ ] 5. 統合と検証
- [ ] 5.1 C++ 検査と公開シンボルを統合確認する
  - C++ 検査に、包括ヘッダから木を組んで単発描画し、フックを登録したレンダラで描画する確認を追加する
  - 静的・動的の両方でビルドし全テストを実行する
  - 完了状態: C++ 検査がリンク・実行に成功し、静的・動的の両構成で全テストが成功し、動的ライブラリの公開シンボルが設計の公開関数だけである
  - _Requirements: 12.1, 12.2_

- [ ] 5.2 CommonMark 仕様の代表例との一致を検証する
  - 仕様の各節（thematic break、見出し、コードブロック、HTML ブロック、段落、ブロック引用、リスト、エスケープ由来の特殊文字、エンティティ由来の非 ASCII、コードスパン、強調、リンク、画像、オートリンク、生 HTML、改行）から代表例を選び、パース結果と同じ構造・値の木を手組みし、例番号と期待 HTML を仕様から転記する。ファイル冒頭に仕様の版と出典・ライセンス表記を記す
  - 生 HTML と危険な URL を許可した設定で全例を、既定の設定で生 HTML・危険な URL を含まない例を比較する
  - 適合テストのテスト実行ファイルを登録する

  - 描画中に出力先の伸長以外の確保が完了時に残らないことを計測アロケータで確認する
  - 深さ 10 万段の block quote の木と emphasis の木の描画が完了することを確認する
  - 線形性は壁時計の時間ではなく決定的な計数で確認する: 10 万ノードの平坦な文書、深い入れ子の画像、深い block quote について、ノード数 n と 10n の入力で、テスト用フックで数えた訪問回数が木のイベント数と一致すること（子を省略した画像の子孫は 0 回）、出力のバイト数が期待値と一致し線形に増えること、計測アロケータで数えた描画中の確保が出力先の伸長による対数回以下でそれ以外は 0 回であること
  - 完了状態: 描画のテストに追加した失敗注入・深い木・線形性の確認がすべて成功する
