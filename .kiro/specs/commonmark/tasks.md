# Implementation Plan

> 前提: foundation、node-tree、parser-core、html-renderer の実装（ビルドの骨組み、エラー列挙、アロケータ、スライス、バッファ、UTF-8、テスト基盤と差し替えアロケータ、標準ノード種別と編集 API、パーサエンジンと拡張・方言の API、HTML レンダラ）が完了していること。本計画のタスクはすべてそれらの公開 API とテスト登録の規約の上に積む。
>
> 並行実行について: 1.2 で全 17 拡張の骨組みのソースをビルドに登録するため、後続の構文のタスクは自分のソースだけを書き換えるが、ブロック・インラインの境界のテストは共通のテストファイルに追記し、構文の間にも実装順の依存（共通部品 → ブロック構文 → インライン構文 → 統合）があるため、`(P)` を付けない。
>
> 適合テストについて: 抽出器と実行ファイルは 1.4 で作り、途中のタスクでは手動の報告（節ごとの一致数）として使う。全 652 例の一致を CTest の合格条件にするのは 6.2 である。
