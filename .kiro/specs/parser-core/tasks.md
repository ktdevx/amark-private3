# Implementation Plan

> 前提: foundation と node-tree の実装（ビルドの骨組み、エラー列挙、アロケータ、スライス、バッファ、UTF-8、テスト基盤と差し替えアロケータ、ノード・種別・レジストリ・編集・イテレータ・正規化）が完了していること。本計画のタスクはすべて両者の公開 API とテスト登録の規約の上に積む。
>
> 並行実行について: 各タスクはライブラリのソース一覧・テスト登録・テスト用拡張（テスト補助の同じソース）に追記し、さらに実装順の依存（拡張 → 方言 → 解析の骨組み → ブロック段階 → インライン段階 → 統合）があるため、`(P)` を付けられるタスクはない。
>
> テスト用拡張について: CommonMark の規則を簡略化したテスト用の構文は、テスト補助のソースに置き、各タスクで必要な構文を追加していく。ライブラリ本体には入れない。

- [ ] 3. 解析の骨組み: 入力の前処理とフォールバック
- [ ] 3.1 入力の前処理と行の取り出しを実装する
  - 分割された入力を連結し、LF・CR LF・単独の CR を行末として行を確定する。断片の末尾の CR、途切れた多バイト文字、先頭 3 バイトが揃わない BOM の判定は次の断片か終了まで保留する
  - NUL と不正な UTF-8 の最大部分列を U+FFFD に置き換え、先頭の BOM だけを除き、行末のない最後の行を終了時に返す
  - 確定した行の分を前詰めし、未完成の 1 行と途切れた数バイトだけを保持する
  - 完了状態: ライブラリがビルドされ、振る舞いの確認は 3.4 の前処理のテストで行えるように、パーサから使う内部の窓口が揃っている

- [ ] 3.4 前処理・フォールバック・状態遷移のテストを書く

  - フォールバックのテスト: 空白だけの行が空行になること、行頭・末尾の空白の除去と行の連結、空行だけの入力
  - 分割供給のテスト: 上の入力を全分割点の 2 分割と 1 バイトずつで供給して一括と同じダンプになること、長さ 0、参照先のない入力、終了後の拒否、リセット後の再利用、オプションの既定値と範囲外、破棄済みの文書への非影響
  - 3 つのテスト実行ファイルを登録する
  - 完了状態: 前処理・フォールバック・分割供給のテストが成功し、計測アロケータで全テストの後片付け後に生存ブロック数が 0 になる

  - テスト用拡張に、段落を全部引き取る見出し相当、末尾 1 行を引き取るテーブル相当（セルをインライン対象に登録）、参照定義相当の段落の内容の処理器、リストの tight / loose の設定を加え、段落のテスト実行ファイルを登録する

- [ ] 5. インライン段階
