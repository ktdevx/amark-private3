# Implementation Plan

> 前提: foundation、node-tree、parser-core、html-renderer、commonmark の実装が完了していること（ビルドとテスト登録の規約、差し替えアロケータ、手組みの木の補助、`render_core`、CommonMark の簡易パース、spec 0.31.2 と例の抽出器）。本計画はそれらの公開 API と規約の上に積む。
>
> 並行実行について: タスク 1.1 と 1.2 は触るファイルが重ならないため `(P)` とする。2 以降の各タスクはライブラリのソース一覧とテスト登録の同じビルド定義ファイルに追記し、実装順の依存（行の管理 → 符号化 → 組み込み出力 → 強調 → フック → 往復）があるため `(P)` を付けない。

- [ ] 1. 基盤: 上流への変更と公開ヘッダ
- [ ] 1.1 (P) 共通の走査駆動部で、子を省略したノードの EXIT を訪問するように直す
  - 子の省略が要求された非葉ノードについて、イテレータの位置を EXIT に移した後、同じノードの EXIT で訪問関数を呼び、エラーならその値を返すようにする。以後の走査は EXIT の続きから進む
  - HTML のフックのテストに、子を省略したノードの EXIT でフックが呼ばれることの確認を追加する
  - 完了状態: HTML のフックのテストで「子の省略の後に EXIT が 1 回呼ばれ子孫は呼ばれない」ことが確認され、html-renderer と commonmark の既存のテスト（適合テストを含む）がすべて成功する
  - _Boundary: RenderCoreFix_
  - _Requirements: 11.3_

- [ ] 1.2 (P) Unicode の句読点・空白の分類を基盤層の非公開モジュールへ移す
  - commonmark の句読点（一般カテゴリ P と S）と Zs の表、およびその判定を、レンダラからも使える非公開モジュールへ移し、commonmark の文字分類はそれに委譲させる。大文字小文字の畳み込みの表は commonmark に残す
  - 表の生成器が 2 つのファイルを出力するようにし、両方の先頭に出典・版・SHA-256・ライセンスを記す。第三者の表記の対象ファイル名を更新する
  - 移したモジュールをライブラリのソース一覧に追加し、動的ライブラリから公開しない
  - 完了状態: commonmark のデータのテストと仕様適合テストが移設前と同じ結果で成功し、動的ライブラリの公開シンボルが増えていない
  - _Boundary: UnicodeClass_
  - _Requirements: 6.5_

- [ ] 1.3 Markdown レンダラの公開ヘッダを宣言し、利用者の義務を文書化する
  - 設計どおりに見出し形式と line break の形式の列挙、設定の構造体、レンダラとコンテキストの不透明型、フック関数の型、設定・レンダラ・単発描画・コンテキスト操作（html-renderer と同じ意味のものと Markdown 固有のもの）の関数を宣言する
  - ヘッダ冒頭に、フックから木を変更しないこと、コンテキストを呼び出しの外で使わないこと、描画中に登録や破棄をしないこと、種別の出所のレジストリをレンダラより長く生かすこと、登録後のレンダラは複数スレッドから同時に描画してよいこと、フックが書いた内容とフックを持つ種別に隣接する強調は再パースの保証の対象外であることを記す
  - 包括ヘッダに新しいヘッダを追加する
  - 完了状態: ヘッダ単独 include 検査で新しいヘッダが単独でコンパイルでき、既存のテストがすべて成功する
  - _Requirements: 10.8, 11.10, 12.1, 13.3_

- [ ] 2. 行の管理と描画の入口
- [ ] 2.1 行の書き出し部を実装する
  - 区切り（行頭保証・空行保証）を保留して次の内容の書き込みでまとめて書き出す仕組み、行頭プレフィックスの段の積み降ろしと指定の段数への復帰、プレフィックスとリスト記号に由来する行末の空白の除去、行の状態（行頭・印のみ・内容）と行の内容の先頭の判定、桁の計数、数値文字参照の書き込み、組み込みの text が書いた最後の文字の置換、終了処理（ブロックの起点だけ改行 1 つで終える）を実装する
  - 生の書き込みでは改行ごとに行末処理を行い、次の行の先頭にプレフィックスを付ける。改行を含むプレフィックスは拒否し、そのノードで積んでいない段の削除は状態が不正であることを示すエラーにする
  - 判定はこの描画で書いた内容だけを見て、出力先に既にあった内容を見ない
  - 新しいソースをライブラリのソース一覧に追加し、内部関数は公開しない
  - 完了状態: 静的・動的の両方でライブラリがビルドでき、動的ライブラリの公開シンボルに内部関数が含まれない（振る舞いはタスク 2.2 以降のテストで公開 API から検証する）
  - _Requirements: 1.7, 1.8, 1.9, 2.15, 11.6, 11.7_

- [ ] 2.2 設定、レンダラの寿命、訪問関数、描画の入口と巻き戻しを実装する
  - 設定の既定値の初期化と検証（各記法の未定義値を拒否）、レンダラの生成（設定の複製、フック表の初期化、確保失敗で出力引数を変えない）と破棄、フック登録（共通のフック表に委ね、種別が空なら拒否）を実装する
  - 訪問関数は子を取りうるノードの ENTER でフレームを積み、フックがあればフックを、なければ組み込み出力を呼び、EXIT（葉では呼び出しの後）でプレフィックスを ENTER 時の段数に戻してフレームを降ろし、強調とリストの記号を親のフレームに記録する。フックのない拡張種別はブロックなら区切りだけを行う
  - 単発の描画とレンダラによる描画は、作業領域をスタック上のコンテキストに用意し、失敗時は出力先を開始時の長さへ戻し、成功・失敗とも作業領域を解放する
  - この時点の組み込み出力は document、paragraph、text（エスケープなし）と、ブロックの区切りだけを持つ
  - 描画のテスト実行ファイルを登録する
  - 完了状態: 描画のテストで引数エラー、未定義の設定値の拒否、既存内容への追記（既存内容が改行で終わらなくても先頭に改行を足さない）、2 つの段落の間の空行 1 つ、ブロックの起点の末尾の改行 1 つとインラインの起点の改行なし、同じ入力での同一出力、描画前後で木が不変、破棄後に生存ブロック数が 0 であることが確認され成功する
  - _Requirements: 1.1, 1.3, 1.4, 1.5, 1.6, 1.7, 1.8, 1.9, 2.1, 2.2, 7.1, 7.3, 7.4, 10.1, 10.2, 10.3, 10.4, 10.5, 10.6, 10.7, 10.9, 11.8, 12.2, 12.3, 12.5, 12.6, 13.4_

- [ ] 3. 符号化と組み込み出力

  - 設計のエスケープ表どおりに、常にエスケープする記号、単語内でない `_`、`[` の前と link の前の `!`、文字参照になりうる `&`、行の内容の先頭の `# > - + = ~` と数字の後の `.` `)`、ATX 見出しの中の `#`、行頭と行末の空白・タブの数値文字参照、制御文字の数値文字参照を実装する
  - リンク先（空・空白・制御文字を含むなら山括弧の形、それ以外は括弧などをエスケープする形）、title（二重引用符、改行は参照）、info string、コードスパンの最短の未使用のバッククォート数と両側の空白、フェンスの文字（info にバッククォートがあればチルダ）と長さ、オートリンクの形の判定を実装する
  - 組み込みの text をこのエスケープで出力するようにする
  - エスケープのテスト実行ファイルを登録する（リンク・コードの出力はタスク 3.4 で追加する）
  - 完了状態: エスケープのテストで text の表の各行（行頭の各記号、`1.` `10)` `1234567890.` `-1.`、単語内と単語の端の `_`、`&amp` と `& `、行頭行末の空白、`\n` と制御文字）の出力が期待どおりで、各出力を commonmark で再パースした段落の text が元と同じになり成功する

- [ ] 3.2 リスト以外の標準ブロック種別を出力する

  - 完了状態: ブロックのテストで各種別の出力、document 直下での見出しの形式の選択、同じ行のリスト記号を伴わない区切り線の文字、内容に長いバッククォートの並びを含むコードのフェンス長、入れ子のブロック引用の各行のプレフィックスと空行の `>`、コード内の空白が保たれ行末の印の空白が除かれることが期待どおりで、再パースした HTML が元と一致して成功する

- [ ] 5. 統合と検証
- [ ] 5.1 CommonMark 仕様の全例で往復テストと冪等性テストを行う
  - 仕様 0.31.2 の全例を抽出器で読み、例ごとに CommonMark 方言でパースして本レンダラで出力し、再パースし、両方の木を生 HTML と危険な URL を許可した設定で HTML にしてバイト比較する。再パースした木を同じ設定で再び出力して 1 回目と比較する

  - 失敗した例は番号・節・入力・出力した Markdown・比較した 2 つの出力を報告し、件数が 1 以上なら失敗させる。理由を設計文書に記した例だけを載せる除外一覧（初期は空）を持ち、除外した数を報告する
  - 往復テストのテスト実行ファイルを、仕様のファイルの場所を渡すコンパイル定義付きで登録する。往復のためのコードはテスト側だけに置く
  - 完了状態: 往復テストが 4 組の設定すべてで全 652 例の往復と冪等性に成功し（除外 0 件を目標。除外がある場合は設計の表現できない木の表に理由が記されている）、処理後に計測アロケータの生存ブロック数が 0 になる
